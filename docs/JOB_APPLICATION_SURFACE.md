# Job application surface

How to use this Tower when applying for remote AI development roles.

## Positioning

Lead with the **flagship pipeline** and the strongest advanced exhibits:

1. Python async orchestrator (agents / control plane)
2. Evaluation harness (isolated scoring + promotion digests)
3. TypeScript MCP gateway (contracts / safety at the interface)
4. Rust safety governor (authority / fail-closed policy)

Emphasize:

- Tool selection under constraint (W4H)
- Explicit evidence classes (no overclaiming)
- Multi-language composition with versioned contracts
- Evaluation and receipts as first-class artifacts
- Willingness to keep hardware/service floors gated until real evidence exists

## Suggested talking points

- “I treat technology choice as an engineering decision with proof gates, not a preference list.”
- “Every advanced exhibit owns a boundary, shows failure modes, and emits a receipt.”
- “Evaluation is part of the system, not a slide. Cases are isolated, timed, and digested.”
- “Gated floors stay gated until real evidence exists — I will not claim CUDA or pgvector success without the runtime.”

## What not to claim

- That this is a 40-language production platform (it is a focused, high-signal map).
- That service- or hardware-gated floors are currently executable in CI without the declared dependency.
- Invention of standard algorithms; the value is synthesis, governance, evaluation discipline, and honest evidence.
